## E011 — Isolated Evaluation Runner

### Hypothesis

Enforceable role/context isolation can produce valid held-out result artifacts for E004-E006 without leaking held-out stimuli or evaluator-only expectations into candidate development.

### Why this experiment exists

The E004-E006 precommit policy correctly declared isolation requirements, but the current AutoResearch runtime does not itself enforce them. Run 005's context has already observed held-out/evaluator material, so merely instructing the same context to "ignore" it would invalidate blind evaluation.

### Precommit

Reuse immutable v1 datasets and hashes from:
- `autoresearch/evaluations/E004_E006_PRECOMMIT_MANIFEST_V1.md`

No edits to v1 datasets are permitted.

Use the role contract in:
- `autoresearch/policies/EVALUATION_ISOLATION_AND_PROMOTION_CONTRACT_V1.md`

Preferred execution order:
1. E006
2. E005
3. E004

### Roles

- R0 dataset steward
- R1 candidate evolver, development data only
- R2 held-out runner, frozen candidate + held-out stimuli only
- R3 evaluator, outputs/traces + evaluator key only
- R4 promoter/human reviewer

Each role records an exposure receipt.

### Metrics

Primary:
- held-out/evaluator leakage incidents
- candidate writes to evaluation artifacts
- valid result artifacts produced
- evaluation-tuple completeness
- reproducibility from frozen candidate/version receipts
- negative/null result preservation

Secondary:
- orchestration overhead relative to a non-isolated dry-run
- number of manual interventions
- contaminated-run detection accuracy

### Success gate

E011 succeeds if:
- zero held-out/evaluator-key leakage into R1 before candidate freeze;
- zero candidate/evolver writes to frozen evaluation artifacts;
- zero evaluator mutation of candidate or execution records;
- at least **two valid result artifacts among E004-E006** by 2026-09-22;
- every valid result has a complete evaluation tuple + exposure receipt + candidate freeze receipt;
- all negative/null results are preserved;
- measured isolation overhead is <=30% versus a comparable non-isolated dry-run, or higher overhead is explicitly justified by validity gain.

### Failure conditions

- a held-out prompt enters R1 before candidate freeze;
- evaluator expectations are visible to R2;
- candidate changes after held-out output is observed;
- evaluation data change without new version/hash;
- result artifact lacks contamination status.
