## Executive Readout

Run 007 finds a convergence that materially sharpens the AI OS architecture:

> Long-horizon agents need an explicit **current belief state** that is validated against evidence, while durable memory remains an archive. Recalled history must be checked against the current environment before it can influence action.

## 2. What Changed Since Run 006

### 2.1 Memory → belief-state control

**FACT** — PoS / “Beyond Memory” (2026-10-01) argues that retaining/compressing history is insufficient for long-horizon control. It maintains an explicit task-conditioned belief consisting of current world state, objective, unresolved epistemic gaps, and unresolved achievement gaps. A Belief Sentinel validates candidate updates against consistency and evidence, while progress monitoring detects “Belief Trapping” and triggers recovery.

**INFERENCE** — D-AR-017 should evolve from supersession-aware fact resolution into a stronger current-belief primitive. “What is current?” is necessary but not sufficient; the control state must also represent what remains unknown and what remains undone.

### 2.2 Historical evidence needs validity-at-read-time

**FACT** — MemTrace (2026-10-04) stores immutable execution traces and dependencies, then checks whether historical evidence is still valid against the current repository state before restoring it into working context. It reports large gains on long-horizon coding benchmarks under the tested harness/backbone.

**INFERENCE** — Memory retrieval needs a **rehydration validator**:
1. retrieve candidate evidence;
2. resolve supersession/authority;
3. compare against current environment/version;
4. inject only evidence still valid for the next action.

This is stronger than ordinary provenance.

### 2.3 Parallel research memory is becoming graph-native

**FACT** — Continual Graph Memory / Ansatz (2026-10-02) stores facts, plans, counterexamples, and their relationships across long-running parallel mathematical research. Dependency-aware retrieval and an evidence-sensitive curator update the frontier; scoped recall brings old claims back for local re-checking rather than blind reuse.

**INFERENCE** — For Hermes/AutoResearch, negative results and counterexamples should be first-class graph objects. A failed route can be as valuable as a successful one if it prevents repeated exploration.

### 2.4 Recursive improvement has moved from concept to sustained run

**FACT** — AIDE² / “Recursive self-improvement of AI research agents” (submitted 2026-09-22) repeatedly rewrites the research agent’s own code, benchmarks candidates on hidden evaluations, and keeps the best version. In an autonomous eight-day run it reports seven successive improvements that transfer to four held-out benchmarks; on a separate held-out family, reward-hacking rate fell from 55% to 32% even though that property was not explicitly optimized.

**INFERENCE** — D-AR-011/012/019 are pointed in the right direction: recursive improvement can work, but hidden evaluation and promotion boundaries are not implementation trivia — they are the core enabling substrate.

### 2.5 Evaluation evidence should bind to the exact candidate

**FACT** — FORALL-LEAN-AGENT (2026-10-01) combines isolated workspaces, fresh review, statement comparison, axiom audits, and independent proof checking. Verification evidence and reviewer decisions are bound to the same candidate artifact rather than relying only on aggregate pass counts.

**RECOMMENDATION** — Amend D-AR-010 so every consequential acceptance receipt binds:
- candidate hash/version;
- verifier version;
- evidence;
- reviewer decision;
- exact environment/config.

A passing signal about candidate A must never drift onto candidate B.

### 2.6 The native ChatGPT stack became an AI-OS substrate

**FACT** — On 2026-09-29 OpenAI introduced:
- **Dots**: always-on agents with goals, memory/context, connected apps, their own cloud computer, and user-defined autonomy boundaries;
- **Space + Pages**: collaborative durable pages/files/artifacts in ChatGPT;
- **Site automations**: recurring cloud schedules linked to published Sites;
- **Codex Cloud**: reusable repository/tool/dependency environments where each task receives an isolated workspace;
- GPT-6.1 Sol in Work/Codex.

**INFERENCE** — The native stack now exposes almost every plane we have been designing separately:

```text
Scheduled Tasks / GitHub events
        ↓ triggers
Dot
        ↓ persistent responsibility / ongoing attention
Space + Pages / Sites
        ↓ shared cognitive surface
Work / Codex
        ↓ execution
Codex Cloud
        ↓ isolated execution cells
GitHub / databases
        ↓ canonical state
```

This does **not** make Dot memory canonical. It does reduce the amount of custom plumbing required to prototype the architecture.

### 2.7 Ponder’s role changes by comparison, not by product change

**FACT** — Ponder’s public beta remains centered on collaborative agents, intelligent tools, action plans, direct editing, execution tracking, synchronized views, and version history.

**INFERENCE** — E007 should now compare:
- **Ponder** as a purpose-built cognitive cockpit,
versus
- **ChatGPT native**: Dot + Space/Pages + Site + Tasks.

The test should use identical GitHub canonical state. The question is no longer “which UI is prettier?” but “which surface improves governed review, state comprehension, and safe action?”

## 3. Frontier Synthesis

The strongest current architecture is now:

```text
authoritative events / environment
        ↓
reconciled current state
        ↓
explicit belief state
  - world state
  - objective
  - epistemic gaps
  - achievement gaps
  - active gap
        ↓
task-specific harness
        ↓
memory/retrieval kernel
  - factual archive
  - state history
  - episodic traces
  - procedural skills
  - governance rules
        ↓
rehydration validity check
        ↓
execution
        ↓
artifact + immutable trace
        ↓
grounded verifier
        ↓
isolated evaluator
        ↓
artifact-bound acceptance receipt
        ↓
retention / causal analysis
        ↓
human promotion gate
        ↓
versioned update
```

The key distinction is:

> **Memory is what the system can recall. Belief state is what the system currently acts as though is true and unresolved.**

## 4. Hidden Unlocks

### Unlock 1 — Belief state is a control plane, not a summary

A compact state object can carry:
- current entities/states/relations;
- confidence/provenance;
- unresolved epistemic gaps;
- unresolved achievement gaps;
- active gap;
- progress health.

This is a stronger decision substrate than raw history or a generic “summary.”

### Unlock 2 — Validate memory when it re-enters cognition

Historical memory can be perfectly retrieved and still be wrong **now**.

Add:
`retrieve → authority/supersession check → environment/version validity check → inject`.

### Unlock 3 — Negative knowledge should compound

Counterexamples, failed branches, and invalidated assumptions should survive as typed graph objects so parallel/repeated research does not pay the same failure cost again.

### Unlock 4 — Codex Cloud can become the E011 isolation substrate

Because Codex Cloud tasks use isolated workspaces, it is a promising implementation path for:
- R1 candidate builder;
- R2 held-out runner;
- R3 evaluator.

Transfer only frozen hashed artifacts between stages. Do not share the whole workspace.

This remains a recommendation until tested.

### Unlock 5 — Dot can own responsibility without owning truth

A Dot could become the always-on “AutoResearch steward” that watches open loops and launches scoped work. But its internal memories should remain operational cache. Governance changes still require explicit GitHub writeback and review.

### Unlock 6 — Space/Sites can become the cockpit baseline

ChatGPT now has a native Ponder-like layer:
- Space/Pages for durable collaborative artifacts;
- Sites for interactive dashboards;
- Site schedules for recurring cloud updates.

E007 should use this stack as the native baseline.

### Unlock 7 — AIDE² suggests a later meta-loop

Once E011 is real and enough accepted runs exist:

```text
AutoResearch code/harness
→ candidate rewrite
→ hidden eval
→ historical-retention eval
→ reward-hacking checks
→ promote/reject
→ next version edits itself
```

This is explicitly **not** ready for activation today.

## 7. Experiments for the Next 14 Days

### E011-A1 — Capability-Broker Dry Run

**Result: PASS at policy-enforcement layer; full E011-A remains PARTIAL.**

A deterministic synthetic broker enforced:
- R1 dev-only reads;
- candidate freeze before held-out access;
- R2 held-out access but no evaluator-key access;
- output freeze before R3 evaluation access;
- permanent denial of evaluator material to R1.

Two deliberate forbidden reads were blocked and logged.

Limitation:
This does not prove separate LLM-context/process isolation. It proves the proposed capability-gating semantics are mechanically enforceable.

### E011-A2 — Isolated Workspace Transfer Test

**Next P0 experiment.**

Use separate isolated execution workspaces (Codex Cloud if available; otherwise independent containers/process identities).

Protocol:
1. R1 receives development assets and writes a candidate.
2. Freeze candidate hash.
3. Transfer candidate only to R2.
4. R2 receives held-out fixture and writes immutable outputs/traces.
5. Freeze output hash.
6. Transfer outputs only to R3.
7. R3 receives evaluator key.
8. Generate exposure and artifact-binding receipts.

Pass:
- zero forbidden exposures;
- independent workspace identity for all roles;
- frozen hashes preserved;
- seeded leak attempt detected;
- candidate/evidence/evaluation hashes bind correctly.

### E011-B — Grounded Evaluation Calibration

Run after A2.

Use >=20 tasks with objective completion signals. Compare grounded completion, deterministic artifact rubric, and LLM judge. Define an abstention threshold and prevent judge-only override of failed grounded completion.

### E009-A — Belief-State + Validity Wrapper

Conditional on E011-A2/B progress.

Use >=24 mutable-state cases with stale evidence.

Baseline:
retrieval + historical context.

Treatment:
explicit belief state + supersession resolution + read-time environment-validity check.

Metrics:
- current-state accuracy;
- stale-evidence leakage;
- task completion;
- token cost;
- false invalidation;
- recovery from deliberately stale evidence.

### E007 — Cockpit comparison update

If Ponder access is available, compare Ponder against Dot + Space/Pages + Site over the same GitHub state.
