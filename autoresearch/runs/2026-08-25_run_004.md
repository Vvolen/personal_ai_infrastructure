## 2. What Changed Since Run 003

### Harness continual learning and forgetting

**FACT** — *Harness Continual Learning* (2026-08-19) formalizes adaptation across prompts, memories, tools, skills, and routing rules around a frozen model. It names degradation of previously reliable behavior after harness updates **harness-level forgetting** and uses guarded commitment that checks current improvement, historical retention, and validity.

**INFERENCE** — A frozen governance anchor is necessary but insufficient. A compliant task harness can still forget old capabilities.

**RECOMMENDATION** — Add a historical-retention suite to E004 and to any future harness promotion gate.

### Harness optimization is becoming diagnosis -> patch -> validation

**FACT** — *AutoSaddler* (2026-08-24) combines failure-trace diagnosis, structured targeted harness patches, and validation-based update selection. *Task-CoEvolve* (v2 2026-08-24) adaptively selects validation tasks on which candidate harnesses disagree and reports matching full-set final performance with 80% fewer evaluations in its experiments.

**INFERENCE** — The useful frontier loop is becoming compiler-like: `failure -> typed diagnosis -> minimal patch -> discriminative validation -> guarded commit`, not generic reflection followed by wholesale prompt rewriting.

### Memory evaluation moved from recall to evolving state

**FACT** — *Can Agent Memory Systems Track Evolving State?* (2026-08-20) introduces StateMemBench with 234 multi-session scenarios where facts, constraints, and decisions are revised. It distinguishes current state from superseded state. StateMem explicitly models supersession and relational dependencies and reports strong gains; a lightweight state wrapper also improves multiple existing memory/retrieval backends.

**INFERENCE** — The harder memory problem is not retrieving history; it is resolving which historical statement is currently valid.

**RECOMMENDATION** — Add a backend-agnostic state-resolution layer with revision semantics above whichever memory substrate is used.

### No universal memory substrate

**FACT** — *Harness the Memory* (2026-08-15) evaluates many memory substrates under one harness and reports no universal winner. Broad retrieval can help factual QA but hurt sequential decision-making by displacing action-critical context.

**INFERENCE** — Memory routing belongs in task-specific harness profiles rather than one global backend decision.

### Causal diagnosis needs interventions

**FACT** — *When Failures Propagate* (2026-08-20) injects known retrieval faults and re-executes downstream agentic-RAG trajectories. Post-hoc coverage diagnosis degrades sharply at later hops, while counterfactual probes recover more signal in a smaller exploratory slice.

**INFERENCE** — After downstream adaptation, the final trace may be a poor witness to the original failure.

**RECOMMENDATION** — Amend proposed D-AR-012: high-impact adaptive trajectories should use replay, interventions, ablations, leave-one-out, or counterfactual probes where feasible; post-hoc trace inspection alone is insufficient causal evidence.

### Long-horizon oversight is shifting toward authorization drift

**FACT** — *Beyond Suspicious Steps* (2026-08-18) proposes an online Role/Goal/Evidence monitor over trajectory prefixes, with deterministic state updates after structured extraction, to detect cases where locally plausible actions drift away from the authorized task.

**INFERENCE** — Long-running orchestration needs goal/role/evidence drift monitoring in addition to tool permissions and end-state evaluation.

**SPECULATION** — A lightweight version may become useful inside Hermes, but it needs local evaluation first.

## 3. ChatGPT Tasks, Projects, and Ponder-Like Workspaces

**FACT** — OpenAI's August 2026 updates let eligible projects switch between default and project-only memory. Project-only memory references chats inside that project, blocks outside-project memory/context, and makes ChatGPT Work unavailable inside that project.

**INFERENCE** — Project-only memory is an isolation boundary, not a canonical-state system.

**FACT** — Computer History on macOS can let ChatGPT and Codex reference selected app/site interaction events. It is off by default, user-inspectable/deletable, and does not record screenshots, screen recordings, microphone input, or system audio.

**RECOMMENDATION** — Treat Computer History as ambient context reinstatement and source-location memory, never as authority for durable doctrine or state.

**FACT** — Google Drive files/folders can now be browsed from Library and kept linked to their Drive source while used in Chat/Work.

**RECOMMENDATION** — Prefer source-linked references when possible rather than copying documents into more stores.

**FACT** — Scheduled Tasks still cannot access project-uploaded files, cannot run more than hourly, and remain oriented toward reminders, recurring work, briefings, and monitoring.

**INFERENCE** — D-AR-006 survives: Tasks are triggers, not canonical state.

**FACT** — Ponder's public beta continues to present an AI workspace centered on intelligent tools, collaborative agents, action plans, execution tracking, version history, and multi-surface views.

**INFERENCE** — Ponder still belongs in the cockpit/interface layer. The comparison is now more interesting because native ChatGPT increasingly offers a Ponder-like bundle through Projects + Sites + Computer History.

**RECOMMENDATION** — Reframe E007 from `Ponder vs Site` to `Ponder interactive artifact vs ChatGPT Project + Site + Computer History`, with GitHub as identical canonical state for both lanes.

## 4. Hidden Unlocks

### Unlock 1 — State is a layer above memory
A vector store, graph, wiki, or episodic memory can all contain useful historical material and still answer incorrectly if they cannot resolve supersession.

### Unlock 2 — Context should be functionally isolated
Use separate planes for governance, objective/plan state, execution scratch, evidence/provenance, and ambient reinstatement. Raw subagent traces should not automatically contaminate planning state.

### Unlock 3 — Harness promotion needs retention, not only improvement
Every harness update should prove both current-task gain and historical capability retention.

### Unlock 4 — Causal evaluation should be intervention-aware
If the trajectory adapts after an error, diagnose through controlled replay or perturbation where possible rather than relying only on the final trace.

### Unlock 5 — Experiment debt is a governance metric
A self-improvement loop should expose proposed/running/completed/promoted/rejected/parked/stale experiment counts and age. Otherwise it can create the appearance of compounding while only accumulating ideas.

## 5. Doctrine Updates

All are **proposed**, not active.

### D-AR-016 — Experiment Debt Gate
Before creating new doctrine candidates or more than two new experiments, every run must resolve, execute, explicitly park, or fail prior P0 experiments and record experiment-debt metrics.

### D-AR-017 — Supersession-Aware State
Durable state for mutable facts, constraints, decisions, plans, and preferences must represent revision semantics and resolve current state before historical recall influences action.

Minimum fields: `valid_from`, `valid_to`, `supersedes`, `superseded_by`, `depends_on`, `status`, `source_refs`.

### D-AR-018 — Functional Context Isolation
Long-horizon agents should separate governance/identity, objective/plan state, execution scratch, evidence/provenance, and ambient/history cues. Subtask traces do not automatically enter persistent plan state.

### Proposed amendment to D-AR-012 — Interventional Attribution
For adaptive trajectories, post-hoc trace inspection is insufficient as the sole causal basis for high-impact promotion. Use replay, controlled interventions, ablations, or counterfactual probes where feasible.

### D-AR-011 through D-AR-015
**RECOMMENDATION** — Do not promote this run. Current external evidence strengthens several proposals, but the precommitted local experiments remain unexecuted.

### E009 — State-first memory wrapper
Compare retrieval-only memory with the same backend plus explicit supersession resolution across 20 precommitted multi-session cases (12 dev / 8 held-out).

Primary metrics: current-state accuracy, superseded-state leakage, source recoverability, retrieval tokens, latency.

Success: >=25 percentage-point leakage reduction OR >=15 percentage-point current-state accuracy gain, with no source-recoverability regression and <=20% latency increase.

### E010 — Functional context isolation
Compare flat accumulated context with isolated plan/execution/evidence planes across 12 precommitted long-horizon tasks (8 dev / 4 held-out).

Primary metrics: completion, constraint retention, objective drift, input tokens, repeated work, recovery after context refresh.

Success: >=20% token reduction OR >=25% reduction in drift/repeated work, with <=5% completion regression.
