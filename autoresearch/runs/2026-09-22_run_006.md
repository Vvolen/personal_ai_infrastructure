## 2. What Changed Since Run 005

### 2.1 Canonical state can be authoritative yet stale

The local sequence is now observable:

```text
authoritative event occurs
        ↓
snapshot is not refreshed
        ↓
next agent reads stale canonical prose
        ↓
agent can reason correctly from an obsolete world model
```

**RECOMMENDATION** — Define the control plane as event history + versioned artifacts, with `STATE.md` as a reconciled compact snapshot.

### 2.2 Dream-RSI turns discovery history into a replay world

**FACT** — Dream-RSI (2026-09-14) keeps the underlying discovery agent fixed and improves the exploration policy. Historical discovery trees become replay simulators for lower-cost off-policy feedback before the improved policy is redeployed online.

**INFERENCE** — Once AutoResearch has enough trajectories, run history can become an offline simulator for improving branch selection, source allocation, stopping policy, parallelization, and escalation without paying for full live research every time.

### 2.3 Memory is moving toward kernel-managed infrastructure

**FACT** — Kernel-Managed Shared Memory (2026-09-09) places retrieval, privacy enforcement, and prompt injection under a system kernel rather than individual agents. Across 1,800 trials, it reports large gains over unmanaged external memory and 15–61% lower end-to-end latency than full-context concatenation while matching full-context performance on two of three tested models.

**INFERENCE** — Hermes should increasingly look like a memory kernel: agents request context; the kernel owns retrieval, authority, privacy, supersession, prompt injection, and logging.

### 2.4 Retrieval can self-improve on the index side

**FACT** — SELF-INDEX (2026-09-17) diagnoses retrieval shortfalls, selectively revises index keys, validates each change before update, and uses a query simulator to explore unseen retrieval demands.

**INFERENCE** — E006 currently asks when to stop retrieving. A mature retrieval architecture has at least four evolvable surfaces: query formulation, source routing, index representation, and stopping/escalation.

### 2.5 Procedural memory is becoming a distinct substrate

**FACT** — Procedural Graphs represents “what to do” as procedure/relation/procedure structures and gates self-evolution on held-out preservation.

**FACT** — MACE (2026-09-18) organizes multi-agent traces into functional units containing conditions, actions, and outputs, connects them through support/conflict/repair relations, and adapts both memory organization and presentation format from execution feedback. It reports 81.11 average across eight benchmarks versus 78.97 for its strongest baseline.

**FACT** — Designer-RSI (2026-09-18) evolves an external procedural skill bank from real user traffic. A matched replay gate accepts repairs only when they do not regress prior observed successes; the paper reports GenEval2 execution success rising from 72.7% to 99.3% on Claude-Sonnet-4 over five rounds.

**INFERENCE** — AutoResearch/Hermes should distinguish factual memory, current-state memory, episodic memory, procedural memory, and governance memory. One undifferentiated vector-store abstraction is insufficient.

### 2.6 Evaluation needs grounded anchors

**FACT** — GAUGE (2026-09-10) compares user-simulator + LLM-judge gates with grounded verifiable task reward across 25 agents. In the reported evaluation, 57.5% of conversations rated satisfied still failed the task, and decision disagreement rose to 31% among close-performing agent pairs.

**FACT** — SWE-Proof (2026-09-18) creates 500 real software tasks with formal verification. Across two frontier models, the authors report that a quarter to a half of test-passing patches still admit formal counterexamples.

**INFERENCE** — Evaluation isolation is necessary but not sufficient: an isolated evaluator can still measure the wrong construct.

**RECOMMENDATION** — When a machine-verifiable outcome exists, use it as the primary promotion signal. Use LLM judges for dimensions that cannot be directly measured and calibrate them against grounded outcomes.

### 2.7 ChatGPT Tasks are now a stronger trigger layer

**FACT** — OpenAI’s current Scheduled Tasks docs support one-off, recurring, monitoring, and event-triggered tasks. Event-triggered Tasks can respond to supported Gmail, Slack, and GitHub activity and run in Work. Eligible paid recurring Tasks can run hourly; event-triggered Tasks can run up to 30 times/hour and 720/day across event-triggered tasks. Tasks created in Projects still cannot access files uploaded/stored in the Project.

**INFERENCE** — D-AR-006 remains correct: Tasks are trigger surfaces, not canonical state.

**RECOMMENDATION** — A GitHub PR-event Task could run a lightweight reconciliation check after review/merge activity so stale state is detected before the next biweekly run. It must not auto-promote doctrine or auto-merge.

### 2.8 Ponder remains a cockpit

**FACT** — Ponder’s current public beta still emphasizes intelligent tools, collaborative agents, action plans, execution tracking, direct editing, synchronized views, and version history.

**INFERENCE** — No verified public product change in this bounded scan alters the current placement:
- Ponder = cognitive cockpit / interactive projection;
- GitHub = governed versioned control plane;
- Hermes = orchestration/runtime;
- memory kernel = governed context service.

## 3. Frontier Synthesis

```text
authoritative events
        ↓
state reconciliation
        ↓
typed objective + permissions
        ↓
task-specific harness
        ↓
kernel-managed state / memory
        ↓
procedural + factual retrieval
        ↓
execution
        ↓
immutable trace + artifact
        ↓
grounded outcome signal
        ↓
isolated evaluator for non-verifiable dimensions
        ↓
retention / causal analysis
        ↓
human promotion gate
        ↓
versioned update
        ↓
replay archive for improving exploration policy
```

The upgrade over Run 005 is that evaluation has two independent integrity requirements:
1. the evaluator must be isolated from the candidate;
2. the evaluator must be anchored to the real outcome rather than merely producing a persuasive score.

## 4. Hidden Unlocks

### Unlock 1 — Run history as replay simulator
Use accumulated real trajectories as a future Dream-RSI-style replay world for improving the research policy offline.

### Unlock 2 — Memory kernel owns authority
Agents request memory; a central layer owns trust, scope, privacy, supersession, budgets, provenance, and write promotion.

### Unlock 3 — Index-side retrieval evolution
The retrieval system can eventually learn how documents should be indexed, not only which query should be issued. Revisions remain versioned and reversible.

### Unlock 4 — Procedural memory as dependency structure
Reusable skills should preserve preconditions, action, output, downstream dependency, conflict, repair path, role, and presentation form.

### Unlock 5 — Matched replay gate
A proposed skill/harness repair must fix the target failure while replaying previously successful cases to block regressions.

### Unlock 6 — Verification hierarchy
Prefer: machine-verifiable completion → environment receipt → deterministic artifact validator → calibrated rubric → calibrated LLM judge → subjective satisfaction.

### Unlock 7 — Event-triggered reconciliation
Use supported GitHub PR events as an interrupt for a lightweight state-reconciliation check between full AutoResearch runs.
