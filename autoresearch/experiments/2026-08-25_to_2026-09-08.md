## E009 — State-first memory wrapper

Hypothesis:
Explicit supersession resolution reduces stale-state leakage compared with retrieval-only memory.

Precommit:
- 20 non-sensitive multi-session state cases.
- 12 development / 8 held-out.
- Every case contains at least one revised fact, decision, constraint, preference, or plan.
- Freeze gold current state and superseded state before running either lane.

Lane A:
Existing retrieval without explicit state-resolution wrapper.

Lane B:
Same storage/retrieval backend plus typed state resolver using:
- `valid_from`
- `valid_to`
- `supersedes`
- `depends_on`
- `status`

Metrics:
- current-state accuracy
- superseded-state leakage rate
- source recoverability
- retrieved tokens
- latency

Success gate:
- >=25 percentage-point reduction in superseded-state leakage OR >=15 percentage-point increase in current-state accuracy;
- no source-recoverability regression;
- <=20% latency increase.

Promotion target:
D-AR-017 Supersession-Aware State.

## E010 — Functional context isolation

Hypothesis:
Separating plan state from execution/evidence exhaust reduces context cost and goal drift without lowering completion.

Precommit:
- 12 long-horizon tasks.
- 8 development / 4 held-out.
- Freeze objective, constraints, done state, and evaluator before lane execution.

Lane A:
Flat accumulated context/history.

Lane B:
- C1 objective/plan state
- C2 execution scratch
- C3 evidence/provenance
- structured handoff from subtask to plan

Metrics:
- accepted completion rate
- constraint-retention rate
- objective-drift incidents
- input tokens
- repeated work
- recovery after forced context refresh

Success gate:
- >=20% token reduction OR >=25% reduction in drift/repeated work;
- <=5% completion-rate regression;
- no increase in unsupported state updates.

Promotion target:
D-AR-018 Functional Context Isolation.
