## Executive Readout

The most important frontier shift is not a new memory database or another agent framework. It is the convergence of **bounded harness self-improvement, causal trajectory attribution, lifecycle context management, and progressive evidence acquisition**.

The operating consequence is:

> AutoResearch should be allowed to evolve task-specific harnesses, but it should not be allowed to evolve the constitution that judges those harnesses during an ordinary run. Changes should be minimal, attributable, held-out tested, reversible, and written back through a reviewable control plane.

This run also found a concrete internal failure: the canonical AutoResearch state exists in GitHub, but no `autoresearch/runs/` directory or canonical run artifacts had been written. The system had a governance design without a completed writeback loop. This run repairs that path through a reviewable branch and PR rather than silently changing `main`.

## 2. What Changed

### A. Task-specific harnesses can now be treated as evolvable artifacts

**FACT** — Hierarchical Self-Improvement (HSI), submitted 2026-08-09, uses one frozen LLM across three scopes: a task harness that executes tasks, an evolver that rewrites the harness, and a meta-evolver that rewrites the evolver strategy under a frozen outer anchor. The paper reports substantial gains on several BALROG environments and also reports a clear capability bound where harness evolution does not rescue tasks beyond the frozen backbone's capability.

**INFERENCE** — This is a better architecture for AutoResearch than unrestricted self-editing. The governance/evidence/safety layer should be the frozen outer anchor; task-specific research harnesses can be mutable.

### B. Evaluation is moving from “did it work?” toward “what caused it?”

**FACT** — Long-Horizon Agent Trajectory Attribution, submitted 2026-08-07, introduces a component schema and more than 1,300 annotated trajectories with tasks for primary-attribution localization and attribution-chain recovery. Baselines include incremental contribution and component leave-one-out perturbation.

**INFERENCE** — A higher run score after a harness edit is insufficient evidence that the edited component caused the improvement. AutoResearch needs attribution before promotion, particularly when multiple context/tool/memory changes occur together.

### C. Context/memory is increasingly framed as a lifecycle rather than a store

**FACT** — Agentic Context Management (2026-07-23) decomposes memory/context management into architecting, ingesting, scoping, anticipating, and compacting/consolidation. It argues that naive append-everything context produces rapidly growing cost and that compaction must be validated for fidelity rather than assumed safe.

**INFERENCE** — “Which memory product should we install?” is too narrow a design question. The real architecture must specify what enters memory, how it is typed, where it lives, when it is retrieved, how it is compacted, what is forgotten, and how source provenance survives those transitions.

### D. Agentic retrieval is converging on progressive evidence acquisition

**FACT** — A recent production-oriented regulatory RAG paper traces a progression from naive RAG to hybrid re-ranking, agentic retrieval, and deep multi-agent retrieval, formalizing the mature design as Progressive Evidence Acquisition with Cost-Aware Escalation: begin with cheaper high-precision retrieval and escalate to deeper reads only when expected evidence gain justifies cost and latency.

**INFERENCE** — The governance loop's fixed retrieval budgets are useful guardrails but should evolve into **evidence-sufficiency stop rules**. Search should stop because the claim is sufficiently supported and contradictions have been checked, not merely because ten sources have been read.

### E. Harnesses are becoming a security and IP surface

**FACT** — Agent Harness Distillation (2026-07-30, explicitly work-in-progress) studies black-box extraction of inference-time harness behavior and reports substantial leakage in its evaluated autonomous multi-agent systems.

**INFERENCE** — As harness quality becomes valuable, copying full internal harness logic into every external tool or shared agent becomes unnecessary exposure. The system should expose capabilities and scoped contracts, not always the full evolution logic.

### F. ChatGPT is moving toward a continuous multimodal execution workspace

**FACT** — On 2026-08-07, OpenAI added file uploads and Projects to ChatGPT Voice, allowing voice conversations to reference recent Project chats, sources, and Project instructions. Voice had already become available in Work and Codex on desktop on 2026-07-23.

**FACT** — On 2026-08-04, long pastes over 10k characters became attachments across ChatGPT plans, explicitly to avoid consuming the entire conversational context window.

**INFERENCE** — Voice can now serve as an intake/control surface for durable projects, while attachment/context handling is becoming more explicit. The right pattern is voice -> structured brief/state artifact -> agent execution, not voice -> ever-growing chat history.

### G. Scheduled Tasks are materially more capable than the bootstrap playbook assumed, but the architectural boundary remains

**FACT** — OpenAI currently documents one-off, recurring, and monitoring Scheduled Tasks. Monitoring remembers previous runs. Current active limits are Go 3, Plus 5, Business/Edu 10, and Pro/Enterprise 15. Tasks cannot run more than hourly and may auto-pause after inactivity.

**FACT** — A task created in a Project containing uploaded files cannot access those Project files.

**INFERENCE** — The original doctrine survives: Tasks are good cadence/monitoring surfaces, but file-backed governed runs need an explicit external state source every time.

### H. Workspace Agents now look like reusable workflow objects, not just chats

**FACT** — OpenAI Workspace Agents for eligible Business/Enterprise workspaces can choose models/reasoning, connect apps, custom MCPs, skills and files, run on schedules, use version history, and be triggered through an API. The current API trigger returns `202 Accepted` but no run ID and does not expose the response through the API.

**INFERENCE** — A Workspace Agent can be a reusable execution unit, but its current API trigger is not by itself a sufficient canonical orchestration protocol. External state, audit, and writeback remain necessary.

### I. Ponder remains an interface pattern, not the control plane

**FACT** — Ponder's current public beta describes “Cognitive Artifacts”: persistent interactive checklists, planners, maps, or trackers that users and AI agents can co-edit, share, sync, and keep updated. Its product framing remains conversation -> intelligent tool -> action/execution tracking.

**INFERENCE** — The original H003 separation is strengthened: Ponder fits as a cognitive cockpit and artifact surface. GitHub/Supabase-like layers should remain canonical state. ChatGPT Sites is now a meaningful competing/complementary cockpit surface because Sites can render dashboards, project trackers, portals, prototypes and reports from Work/Codex.

**SPECULATION** — The winning human-AI interface may become “generated task-specific micro-workspace” rather than a universal chat transcript or universal infinite canvas.

## 3. Frontier Scan

### AutoResearch / self-improving systems

The frontier has moved from single-loop “generate -> test -> keep/reject” toward hierarchical improvement where a mutable harness and mutable search/evolver policy operate under a more stable outer anchor. HSI is the clearest recent signal. This matches the existing Bilevel AutoResearch intuition but adds a concrete separation of scopes and empirical limits.

### Cognitive and context engineering

The strongest useful abstraction is no longer “fill the context window.” Context is an actively managed cognitive budget with different lifecycle stages. Durable state, retrieval, temporary working context, procedural skills, and compaction should have separate policies.

### Memory engineering

Memory should be treated as a write/read/consolidate/forget system. Writes need stronger governance than reads because a bad write can contaminate many future trajectories. Provenance must survive compaction and consolidation.

### Agentic retrieval

Static top-k RAG is becoming only the first rung. Progressive retrieval with evidence-gain-based escalation is a stronger default: lexical/semantic retrieval first, deeper document reads/graph expansion/subagents only when support or contradiction coverage is insufficient.

### Evaluation loops

The key frontier is causal and trajectory-aware evaluation. Output evaluation answers “was this result acceptable?” Attribution answers “which component made it better or worse?” A self-improving harness needs both.

### Tooling/workflow

OpenAI's Work, Sites, Voice-in-Projects, Scheduled Tasks, and Workspace Agents are converging on an integrated stack of intake, recurring triggers, connected execution, reusable agents, and interactive output surfaces. The missing layer for a personal governed OS is still explicit canonical state and cross-surface writeback.

## 4. Hidden Unlocks

### Unlock 1 — Frozen outer anchor

What most systems miss: self-improvement without a non-self-modifying judge can optimize away the constraints used to evaluate itself.

Small experiment: E004 keeps governance fixed while allowing only a `frontier_scan` harness profile to evolve.

### Unlock 2 — Attribution before promotion

What most systems miss: better final scores can result from noise, model variance, changed context, or unrelated tool behavior.

Small experiment: E005 compares output-only promotion with trajectory/component attribution.

### Unlock 3 — Evidence sufficiency instead of source quotas

What most systems miss: reading more sources can add context sludge without adding decision-relevant evidence.

Small experiment: E006 uses an evidence-sufficiency score to decide whether to escalate retrieval.

### Unlock 4 — Cognitive cockpit as a projection

What most systems miss: a visual workspace becomes dangerous when the interface silently becomes the database.

Small experiment: E007 renders the same canonical manifest in Ponder and a ChatGPT Site while all approvals write back through GitHub.

### Unlock 5 — Voice as an intake compiler

What most systems miss: voice is valuable when it produces typed external state, not when it merely produces a longer transcript.

Small experiment: E008 compiles voice and typed briefs into the same objective contract.

### Unlock 6 — Harness confidentiality

What most systems miss: the better the harness becomes, the more it resembles proprietary operating know-how. Exposure should be deliberate and scoped.

## 5. Doctrine Updates

### ADD D-AR-011 — Frozen Outer Anchor

**RECOMMENDATION** — Ordinary AutoResearch runs may evolve task-specific harnesses and bounded evolver policies, but may not automatically rewrite the governance/evidence/safety anchor. Governance-layer edits require a dedicated audit and human review.

### ADD D-AR-012 — Attribution Before Promotion

**RECOMMENDATION** — High-impact harness changes require evidence that the edited component plausibly caused the improvement. Use trajectory diagnostics, ablations, leave-one-out perturbations, or controlled A/B tests where feasible.

### ADD D-AR-013 — Interface-State Separation

**RECOMMENDATION** — Ponder, ChatGPT Sites, dashboards, and generated workspaces are projections and manipulation surfaces over canonical state. They do not become canonical truth merely because they are more legible.

### ADD D-AR-014 — Harness Exposure Policy

**RECOMMENDATION** — Treat private harness specifications, evolution policies, and evaluator logic as scoped intellectual/security assets. Expose only the operational subset required by each external runtime.

### MODIFY retrieval doctrine — Evidence Sufficiency Stop Rule

**RECOMMENDATION** — Retain hard maximum budgets as safety caps, but allow research to stop earlier when evidence sufficiency, freshness, contradiction coverage, and source authority clear a threshold; escalate only when expected evidence gain justifies cost.

### RETAIN H003 with higher confidence

**INFERENCE** — Current product direction strengthens the existing hypothesis that GitHub or another explicit ledger should be the control plane while Ponder/Sites-like systems are interfaces.
